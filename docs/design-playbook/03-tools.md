# GitHub 上值得用的，和不值得碰的

查于 2026-11-13。判断标准只有一条：**能不能在不推翻现有站的前提下，真的改善观感。**

我们现在的技术栈很轻：Next 16 + React 19 + Tailwind 4 + motion。
没有图标库（图标是手写的 SVG），没有字体包（用系统字体）。

---

## ✅ 值得装（就两个）

### 1. lucide-react —— 统一图标

https://github.com/lucide-icons/lucide

**解决什么**：现在全站图标是十来个手写 `<svg>`，散在各组件里，
线宽有的 1.6、有的 1.5，尺寸有的 18、有的 20，视觉上不齐。
这是「页面看着不精致」最便宜的一个来源。

**代价**：一个包，按需 tree-shake，不会让页面变大。
**风险**：低。图标是纯 SVG，不涉及布局。

### 2. Radix Colors —— 抄它的灰色阶

https://github.com/radix-ui/colors

**解决什么**：我们的边框色、分隔线、卡片底色是零散定的
（`#e3eaf2`、`#eef2f7`、`#e6eef6`、`#dbe3ec`…），彼此差一两个色阶，
远看就是「一片糊」。Radix 的灰阶是 12 档等距明度，直接对应
「边框 / 分隔线 / 次级底 / 主底」四个用途。

**建议用法**：不装包，只把它的 gray/slate 色阶取出来，
加进 `packages/design-tokens/theme.css`，替换掉那些散落的裸值。

**风险**：低。只是换色值，不动结构。

## 🟡 一次性工具（跑完就卸）

### axe-core / pa11y —— 查对比度和无障碍

https://github.com/dequelabs/axe-core

**解决什么**：文字和背景的对比度够不够，有没有只有颜色没有文字的提示。
这一类问题肉眼很难判断，机器一秒就能列出来。

**建议**：改完之后跑一次，把报告里的「对比度不足」挨个修掉，然后卸掉。

## ❌ 别碰

### shadcn/ui、HeroUI、DaisyUI

三个都不合适，原因一样：**它们自带一整套设计语言**。
我们的站已经有自己的令牌和组件，再叠一层就是两套规矩打架。
更关键的是，它们的默认长相（圆角、灰边、卡片）恰恰就是「AI 味」的原型。

### magicui / aceternity 那类动效组件

每个组件都很炫，但都是「一个模块一个风格」。
拼在一起会变成十年前那种「每个区块都在动」的官网。

### 各种「AI 设计 skill」

Hallmark、Impeccable、taste-skill 我都看了。它们是**方法论**，
不是能装进项目的零件。真正有用的是它们的判断标准（第 01 篇），
已经提炼进来了，不需要装。

### 中文字体自托管

现在用系统字体：Windows 上是微软雅黑，Mac 上是苹方，同一个页面两种长相。
统一成一套确实更好看，但中文字体文件 3–8MB，首屏会明显变慢。

**结论**：先不做。真要统一，优先考虑「只给标题用一款」的轻量方案。

---

## 一句话总结

图标统一（lucide）+ 色阶统一（Radix 的灰阶）这两件事，
成本低、风险低、观感提升明显。其他都先放着。
