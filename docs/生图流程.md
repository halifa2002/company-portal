# 生图流程手册

这一份不是通用教程。它把网上的四套公开资料（OpenAI 图像提示词指南、阿里云文生图 Prompt 指南、Scenario 创作流水线、ComfyUI 工作流合集）和本机过去几个月真跑过的出图任务对了一遍，留下的都是**实际验证过、或者实际翻过车**的做法。

里面的数字（压暗系数、裁切位置、体积上限、字数上限、耗时）都来自实际任务，不是估的。

### 0.1 先判断：这活该不该用 AI 生图

不是所有"要一张图"都该调模型。先过这张表：

| 你要的东西 | 该用什么 | 为什么 |
| --- | --- | --- |
| 纯色背景、规整渐变 | CSS | 生图会给你色块感、还多出纹理；CSS 精确可控 |
| 图标、logo、简单几何 | SVG（手写或现成图标库） | 位图放大会软，16px 下糊成一片 |
| 带成句文字的海报、封面、分享卡 | HTML + 截图 | 字必须一个字不错 |
| 流程图、对比图、表格示意 | SVG / HTML | 模型会把连线画错、把字写歪 |
| 照片感、插画、材质、天空、氛围 | AI 生图 | 这是模型真正擅长的地方 |

判据一句话：**这张图的核心是"像素质感"，还是"准确的形状与文字"？** 前者交给模型，后者交给代码。

## 1. 九条铁律

这九条每条都对应一次真实的翻车，不是凭经验总结的空话。

**一、字要准的图，不要交给 AI 生。**
公众号分享卡、抬头图这类"一个字都不能错"的图，正确做法是 HTML 排版 + 无头浏览器截图，或者 Pillow 写字。AI 生图适合做主视觉，不适合做终稿排版。

**二、版式类提示词，第一条必须是保真句。**
凡是"对比图、多要点、多文字排版"这类提示词，开头先写商品保真，再写版式。顺序反了，模型会把注意力全放在排版上，顺手把商品重画成相似的东西。

**三、标签上的字必须原样保留。**
上传图上写什么就照抄什么，中英文数字都照旧，不许翻译、不许改写、不许"优化"。早期有提示词写"只留自编中文小字"，结果把用户的品牌名抹掉了。

**四、提示词里的示例词会被整段照抄。**
给巧克力酱写"建议烹饪时间 11 分钟""简单易煮"，模型真会印上去。必须补一句"示例只示范格式，内容必须与这件商品真实相符，不许照抄示例词"。

**五、改图一次只改一处。**
四个要求一起提，结果一个都没到位，还把原来的好构图丢了。

**六、先小样定方向，再出大图。**
先用 1536×1024 出几张看方向，方向对了再出 2K / 4K。直接出 4K 试方向，一次就是四倍的钱和时间。

**七、窄横条必须裁在细节段。**
裁在云层、纹理、光斑上，像一张天空；裁在纯色区，就是一条色块。本项目实测，横向云霞带的有效区间在整图高度 0.58 到 0.60 一带。

**八、图里的颜色，读者会看见，注释管不住。**
一张转化带图右缘出现过 #7deff8（色相 184°，青绿），已经跑到品牌蓝（#188df9，色相 205°）的隔壁，整页最亮最饱和的一块就在这条带上。代码注释写"杏橘是图里的光、不进色板"没用——读者只看图。

**九、文件带版本号，图片本体一起提交。**
同名覆盖会让聊天框、浏览器、CDN 全部显示旧图；只提交引用不提交图片，线上就是 404。

## 2. 开工前的五个问题

**一问：用在哪？**
整屏背景、页面横条、卡片配图、商品主图、分享封面、图标。位置决定比例，也决定要不要留出文字的位置。

**二问：显示多大？**
按最终显示宽度算，再乘 2（二倍屏）。网页容器常见 1200 到 1440 宽；首屏按 2560 或 3840 出。

**三问：图上要不要有字？**
三种情况分开处理：

| 情况 | 做法 |
| --- | --- |
| 不要字 | 提示词里明确写"不要任何文字" |
| 只要几个大词（促销标题） | 可以让模型写，但要限字数、限处数，见 4.4 |
| 成句中文（说明、标语、排版稿） | 不要交给模型，用 HTML 排 |

**四问：图后面压白字还是黑字？**
压白字，图要够暗（亮度乘 0.7 上下）；压黑字，图要够亮、够干净。

**五问：要几张、出多大？**
先 1 张小样定方向，再 3 张挑，定稿才出大图。

## 3. 第 1 步：把需求写成一张 brief

```
用途：
放哪个页面 / 哪个位置：
比例：
最终显示尺寸：
明暗：压白字 / 压黑字 / 不压字
图内文字：无 / 几个大词（写什么、在哪、几个字）/ 成句（改走 HTML）
必须出现的（3~5 条）：
不能出现的：
张数：先 1 张小样 / 直接 3 张
参考图：无 / 有（第 1 张管什么、第 2 张管什么）
```

**填好的例子（真实的那个）**

```
用途：预览页中段转化带的背景横条
比例：8.5:1（2560×300）
明暗：压白字
图内文字：无
必须出现的：薄丝云、深蓝暮色、看得出是天空、有云层层次
不能出现的：星点、地面、山、鸟、文字、水印
张数：先 1 张
参考图：无
```

这张 brief 写出来，提示词其实就是把它翻成一句话。后面所有争执都围绕"必须出现的"那几条。

## 4. 第 2 步：写提示词

### 4.1 两个公式

**基础（第一次试方向）**

```
主体 + 场景 + 风格
```

**进阶（要质感、要细节）**

```
主体（长什么样）+ 场景（在哪、什么天气光线）+ 风格
+ 镜头语言 + 氛围词 + 细节修饰
```

差别不在长短，在**有没有写形态**。写"云"，出来随便一团；写"薄、疏、细长、有方向感的卷云"，才是你要的那层。

### 4.2 六个维度

**主体：形态、材质、状态**

- 好：`薄薄一层卷云，云丝细而疏，能透出后面的天色`
- 差：`好看的天空`
- 商品类：`磨砂玻璃瓶身，白色泵头，正面标签黑色无衬线`

**场景：地点、天气、时间、视角高低**

- `从云层上方俯拍，看不到地面`
- `室内，靠窗的下午，光从左上斜进来`
- `纯色背景，无环境`

**风格：写媒介，不写形容词**

- `实拍摄影`、`胶片`、`3D 渲染`、`水彩`、`国风水墨`、`扁平插画`
- 要照片感就直说 `photorealistic` 或 `实拍摄影`。相机型号只能当外观提示，别指望它控制景深。

**镜头：景别、视角、焦段**

- 景别：特写 / 近景 / 中景 / 远景
- 视角：平视 / 俯视 / 仰视 / 航拍
- 焦段：广角拉纵深，长焦压空间，微距看材质

**氛围：一条就够**

`安静`、`开阔`、`压抑`、`清晨感`、`暮色`。堆三个以上会互相打架。

**细节：光、颗粒、边缘**

`光从左上打下来，右侧留阴影`、`轻微颗粒`、`地面薄雾，远处虚化`。

### 4.3 保真段（商品类必须写）

这是本机实测最有价值的一条：**版式类提示词从第一条起就写保真，而且要逐项点名结构。**

**模板**

```
商品本身必须与参考图完全一致：形状比例、主体结构、配件、配色、材质纹理、标签上的文字，
一律照原样保留，不要重新设计，不要替换成相似的东西。
只允许改变：____（背景 / 摆放角度 / 图内文字 / 光线）。
```

**真实案例**

一条 303 字的"前后对比·收纳广告"提示词，通篇只讲版式（正中竖线、左右标题、三行说明、红叉绿勾），实测结果：13 处中文全部正确、版式完美，**但商品被换掉了**——上传的是窄长托特包、带黑色抽绳扣和前竖织带，出图变成宽口圆桶包，抽绳扣和织带全丢。

加上保真段、把"包型比例、提手、织带、抽绳扣、配色、布料纹理"逐项点名，末尾写明"只允许改包内物品、摆放角度、背景"，同一张底图复跑，标志性结构全部回位。

结论：**文字多不会让图崩，没有保真句才会。**

### 4.4 图里的文字：三种做法

**一、不要字（推荐）**

提示词末尾写：`画面中不要出现任何文字、水印、logo、边框`。

**二、少量大词（可以让模型写）**

实测可用的组合是"三处文字"：

- 顶部横条：4 个字
- 侧边竖排：两行，每行不超过 5 个字
- 底部横带：不超过 6 个字
- 全部用超粗黑体加描边

例：`品质优选 / 口感浓郁 / 当天发货`，三处都能清晰读出。

超过这个量，字会糊成装饰，看不出是什么。

**三、成句中文（不要交给模型）**

说明文字、标语、排版稿，一律用 HTML 排。这条规矩来自分享卡：分享卡要"字准"，最初就定了"不走 AI 生图，走 HTML + 无头浏览器渲染"。

**一条附加规矩：字号按缩后尺寸定。**
2100px 宽的图，在手机上大约按 750px 显示，130px 的主标题实际只剩约 46px，40px 的副标题只剩约 14px，底栏小字基本糊。定字号时按缩小后的尺寸算，不要按原图算。

### 4.5 三条禁止

**一、不要让模型自造参数。**
模型会自己加 `UPF50+`、`99% 防紫外线`、`建议烹饪时间 11 分钟` 这类没给过的信息。商用有虚假宣传风险。提示词里显式写"不要自造参数、数据、认证、价格"，或者干脆要求"图内不出现任何数字"。

**二、不要写自相矛盾的句子。**
一边写"禁止灰色"，一边要求"密集排线"，模型只能往素描跑。线稿类尤其明显：想要线稿，要写"按漫画家习惯简化重画，头发合并成几束、五官放大、背景留白、明暗只用少量稀疏排线"，不能只写一句"转线稿"——那样出来是"照片加了个素描滤镜"。

**三、不要用同一段开头套一百条。**
风格库里 196 条提示词共用同一个开头模板，只换一句场景，用户的感受就是"都差不多"。写批量提示词时，开头也要换。

### 4.6 五个能直接改的模板

**A 网页背景**

```
薄而疏的高空卷云，云丝细长有方向感，深蓝偏青的暮色天空，没有地面，
实拍摄影，俯拍视角，天空上部更暗、靠近地平线透一点淡粉霞光，
轻微胶片颗粒，安静开阔；画面中不要出现任何文字和水印。
```

**B 商品主图**

```
[保真段：商品形状、结构、配件、配色、材质、标签文字全部照原样]
一瓶磨砂玻璃身体乳，白色泵头，正面标签黑色无衬线字；
浅米色纯色背景，无道具；柔和侧逆光，右侧淡淡投影；
商业产品摄影，主体居中偏下，四周留白。
```

**C 人物**

```
一位 30 岁上下的亚洲女性，短发，米白针织衫，站在窗边侧身看向镜头，
室内下午的自然光从左进来，中景，35mm 视角，浅景深，柔和色调。
```

**D 卡片插画**

```
一只橘猫趴在打开的笔记本电脑上，扁平插画风，米白底，橙色与深灰两个主色，
主体占画面中间三分之一，四周大量留白（留给标题文字），画面中不要出现任何文字。
```

**E 图标**

```
一个由两条折线组成的抽象标记，扁平、纯色、无渐变，线条等宽，
图形居中，四周留出约 12% 的空白，透明背景，16px 下仍能看出轮廓。
```

### 4.7 词表

**光线**：晨光、逆光、侧逆光、侧光、顶光、霓虹、氛围光、丁达尔、柔和漫射

**天气时间**：清晨、正午、黄昏、暮色、阴天、薄雾、雨后、雪后

**材质**：磨砂玻璃、陶瓷、羊毛毡、折纸、水彩纸、金属拉丝、亚克力、织物

**构图**：居中、三分法、对角线、大面积留白、俯拍平铺、特写裁切

**风格**：实拍摄影、胶片、电影感、扁平插画、水彩、国风水墨、3D 卡通、粘土、点彩

**氛围**：安静、开阔、克制、热闹、梦幻、压抑、温暖

**画质**：轻微颗粒、边缘清晰、高细节、柔和过渡

一条原则：**写看得见的东西，不写感觉。**

## 5. 第 3 步：参数怎么定

### 5.1 比例

| 用途 | 比例 | 常见尺寸 |
| --- | --- | --- |
| 网页整屏 / 首屏 | 21:9、16:9 | 2560×1097、3840×1646、2560×1440 |
| 页面横条 | 8.5:1 到 6:1 | 2560×300、2560×394 |
| 过渡带（深浅衔接） | 4:1 | 2048×512 |
| 卡片、手机竖屏 | 3:4、4:5 | 1536×2048、1440×1800 |
| 方形卡片 / 头像 | 1:1 | 1024、2048 |
| 小程序分享图 | 5:4 | 1000×800 |
| 公众号封面 | 约 2.35:1 | 1800×766、900×383 |
| 图标 | 1:1 | 512、1024 |

注意：**比例以参数为准，不以提示词里写的为准。** 提示词里写"3:4"只是语义锚点，实际输出由 size 参数决定。曾有 36 条提示词写的比例和实际 size 不一致，用户看到的是参数那个。

### 5.2 尺寸与"先小样"

1. **小样定方向**：1536×1024 出 3~5 张，看构图和气氛。本机实测过：领导嫌首屏星空"有点花、有点深"，就是用这个尺寸一次性出了 5 个明亮方向候选给他挑。
2. **定稿出大图**：首屏 3840 宽，普通区 2560 宽。
3. **别硬拉**：AI 生成的星云、银河有"涂抹感"，放大铺满会糊；原图不够大又要铺满，必然软。

### 5.3 质量档

- 带小字、多元素、要排版：高档。字糊等于重做。
- 只改一处细节：中档，快，周围不容易被改坏。
- 纯色背景、大块主体：中档够。

### 5.4 张数

先 1 张 → 方向对了再 3~5 张 → 选定基准图才批量。方向没定就批量，是纯浪费。

### 5.5 通道与耗时（本机实测）

- 默认通道：`openai-compat`，模型 `gpt-image-2.5`（生成与编辑同一个）。
- 玩图那个项目有自己的通道（`https://988665.xyz/v1`），key 存在 `~/.dsh/.credentials.yaml`；**key 只留在凭据文件里，不写进文档、不写进仓库**。
- 一张图 20 到 40 秒。
- 插件通道偶发 TLS 握手被掐，稳定的做法是脚本直连出图接口，自带 8 次重试。
- `ECONNRESET`、`SSLEOF` 这类瞬时错误，原样重试（间隔 5 秒、最多 4 次）基本都能过。
- HTTP 400 且是 `content_policy` 拒绝时，原样再跑一次通常就过了——不是提示词的问题。
- 出图通道余额耗尽会返回 403 `insufficient_user_quota`，这不是风格或提示词的问题，先查余额。

### 5.6 出图后先看三处

- 主体对不对（是不是你要的那个东西、那个形态）
- 能不能裁出目标比例（左右有没有余量）
- 有没有硬伤（多余文字、断手、糊掉的边缘）

三处都过再往下走。同一提示词连出两张都同一个毛病，是提示词的问题，别继续抽。

## 6. 第 4 步：改图

### 6.1 原则

**一次只改一处，每次写清什么必须保持不变。**

模型不会"记得上一张"，它只认你这次的图和这句话。不写"保持不变"，它就会顺手把别的地方重画一遍。

### 6.2 通用模板

```
在上一张的基础上，只改：____。
其余全部保持原样：构图、主体位置与比例、光线方向、整体色调、画面比例、边缘细节。
不要重新设计，不要新增任何元素，不要改变画幅。
```

### 6.3 六类改动的写法

**一、调明暗 / 调色**

> 只整体压暗约 20%，保持所有形状、云的位置和边缘不变，不要重新生成画面。

亮度、饱和、色温，一次只调一项。

**二、换背景**

> 只把背景换成纯净浅米色。商品本身保持完全一致：形状、标签、颜色、位置都不要动。

**三、加 / 删元素**

> 只去掉右侧那棵树，其余一切保持原样，被挡住的部分按周围自然补上。

"自然补上"要写，不写会出现一块糊色。

**四、改文字**

> 只把 "SALE" 改成 "NEW"，字体、大小、位置、颜色都不变。

改完放大看其他文字有没有被顺手改掉。

**五、换服装 / 换材质**

> 只把外套换成深灰羊毛，人的脸、发型、肤色、姿态、光线、背景全部保持不变。

对人的时候，把"脸、发型、肤色、姿态"逐条列出来，比"保持人物一致"有效。

**六、扩图**

> 向左右各扩展一倍宽度，补上的部分延续原来的天色和云层走势，不要引入新的主体。

扩完看接缝有没有一条淡竖线。

### 6.4 参考图分工

多张参考图必须分工：

> 图 1 管人物长相和发型，图 2 管外套，图 3 管背景；只替换这三样，脸、姿态、光线不要变。

不分工，模型会自己乱配。

还有一条本机事实：多张参考图会先拼成一张参考板再当单图发，所以**张数不影响出图耗时**——别为了"省时间"少传参考图。

### 6.5 迭代记录

| 轮次 | 改了什么 | 结果 | 下一步 |
| --- | --- | --- | --- |
| 1 | 初始出图 | 云太厚，像积雨云 | 改提示词重出 |
| 2 | 云改薄、去地面 | 方向对了 | 定基准图 |
| 3 | 压暗 20% | 白字能看清 | 裁窄条 |
| 4 | 裁切下移到云层段 | 终于像天空 | 定稿 |

四行就够。不记的话，第三轮开始分不清哪版是哪版。

### 6.6 什么时候重开

- 同一个问题改三轮还没好 → 提示词写错了，回去重写。
- 整体结构错了（构图、主体不对）→ 重出，别修。
- 只有一处局部问题 → 修。

判断标准：**改的是一小块像素，还是整体结构。**

## 7. 第 5 步：落地成能上线的文件

### 7.1 压暗与调色

图后面要压白字时，亮度乘 0.66 到 0.88：

| 系数 | 用在哪 |
| --- | --- |
| 0.66 左右 | 页尾收口、深色区块，白字必须清楚 |
| 0.85 到 0.88 | 只是稍微压一点，保留天空的通透感 |
| 0.80 上下 | 一般转化带、横条 |

压暗会让颜色发灰，饱和度提到 1.1 到 1.2 补回来。

顺序：先压暗 → 把白字真压上去看 → 不清楚再压一点点。压过头会变成一块死板的重色，失去"是天空"的感觉，这也是当初被否掉的一版。

### 7.2 裁切

**窄横条的成败全在裁切位置。**

- 裁在云层、纹理、光斑上 → 像一张天空。
- 裁在纯色区 → 一条蓝带，怎么调都救不回来。

做法：

1. 看整张图，找云层最密、层次最多的一段（通常在中下部和地平线附近）。
2. 从那一段开始裁。
3. 缩略看一眼，像纯色就再往下挪 5%。

本项目实测：横向云霞带的有效区间在整图高度 **0.58 到 0.60**；落到 0.5 以上，容易变成一条纯蓝。

**过渡带的教训：** 曾经做过一张专用的"深浅过渡带"（2048×512，上接星空深蓝、中段天亮、下段落到浅蓝），整段铺上去的效果是"像贴壁纸、中间露一条假亮蓝横带"。后来改成**裁同一张背景图最底部一截**，铺在顶部 220px，再叠一层"透明 → #eef6ff"的白雾把边缘抹平，才自然。

结论：过渡别用另一张图的整段，用同一张图的边角。

### 7.3 压缩与体积

- 转 **webp**，质量 80 到 85。
- 存两档：2K（常规）、4K（首屏）。
- 单张尽量 700KB 以内；实测 4K 星空图（3840×2160）压到 614KB 可用。
- 后台上传类有硬限制：封面 ≤ 850KB，上传接口 ≤ 1MB，超了直接传不上去。
- 照片类别用 PNG，体积大好几倍。

### 7.4 命名

```
语义-版本-尺寸.webp
dusk-band-cloud-v5.webp
dusk-closing-cloud-v6.webp
hero-sky-1.webp
starfield-dawn-4k.webp
```

- **带版本号**：v4、v5、v6，改一版加一号，不覆盖。
- **语义在前**：一眼看出是什么（dusk 暮色、band 横条、closing 页尾）。
- **尺寸后缀**：只有多档时才加 `-2k`、`-4k`。

同名覆盖是最常见的事故：聊天框、浏览器、CDN 都按路径缓存，覆盖以后对方看到的还是旧图。给用户看改版图，必须换新文件名。

### 7.5 提交与部署

- 页面引用了图，**图片文件本体必须一起提交**。只提交引用，线上就是 404（4K 星空图差点就这么漏过一次）。
- 本地打开页面确认加载出来，不是看代码。
- 大图单独确认一次文件大小和是否真在仓库里。

### 7.6 响应式

- 电脑和手机不同尺寸时，给两档文件。
- 手机上如果图被裁得很窄，检查主体有没有被裁掉。
- 背景图配文字时，手机文字换行会变高，留白按手机算。

### 7.7 颜色与品牌

- 图里的颜色会被读者当成页面配色，选图时看色相，别只看好看。
- 转化带那次：图右缘的 #7deff8（184°）跑到品牌蓝（205°）隔壁，成了整页最抢眼的一块。
- 图片自带的主色如果和品牌色打架，宁可在图里压饱和度，也别指望注释解释。

### 7.8 预览版和正式版，图片也要各存一份

这是本项目的硬规矩：预览页用的每个文件都要有独立副本，在预览版上改任何东西都不许影响正式页。图片同样适用。

- 预览页要换背景图，**新建一个文件**（比如 `hero-sky-preview-v2.webp`），不要动正式页在用的那张。
- 不要用"同一张图改样式"的方式复用：`object-position`、滤镜、遮罩都算改动，正式页会跟着变。
- 正式页要改，单独改正式页那一份，两边各留各的版本号。

一次真实的险情：给预览页换过渡时，差点直接覆盖正式页引用的同一张图；两边共用一个路径，覆盖就等于同时改了正式页。

## 8. 五套走法

### 8-A 网页背景（真实案例：深蓝暮色带）

目标：中段转化带和页尾收口要"颜色深、不阴沉、不像乌云、一眼看得出是天空"，还要和首屏蓝天是同一种天空语言。

**走过的弯路**

1. 纯 CSS 深蓝渐变（无图）→ 用户判"要看得出是天空"，废。
2. 暗云海暮色图（深积云）→ 判"阴沉、像乌云"，废。
3. 薄云图但裁切落在无云区 → 带子里仍是一条纯蓝，废。

**最终走通的做法**

1. 出 1 张 2048×1152 的深蓝暮色薄丝云（无星点）。
2. 压暗 0.80（页尾到 0.66），饱和 1.15。
3. 裁成 2560×300（中段）和 2560×394（页尾），裁切位置定在整图高度 0.58 到 0.60。
4. 存 webp，按 `dusk-band-cloud-v5.webp` 命名。
5. 页面换上，截图确认白字清楚、看得出云。

**写提示词时记住**：要"看得出是天空"，就得有云的层次和方向感；要"不阴沉"，就别让云厚到遮住天光。

### 8-B 商品图 / 模板套图（要保真）

1. **定基准图**：先出一张最满意的，作为整套的样子。
2. **写保真段**：商品形状、结构、配件、配色、材质、标签文字，逐项点名。
3. **只允许改什么**写清楚（背景、角度、图内文字、光线）。
4. **一条跑通再复制**，复制时只改变体那一句。
5. **成组看**：并排看色调、光线、构图像不像一家出的。
6. **单独补差**：哪张不合群单独重跑，别整批重来。
7. **统一后处理**：同一套图用同样的压暗、同样的裁切。
8. **归档**：提示词原文和成品放一起。

**两个真实翻车点**

- 提示词写"示例格式"时，模型会把示例内容当真印上去（巧克力酱被写上"建议烹饪时间 11 分钟"）。补一句"示例只示范格式"就好。
- 上传的图本身带文字色框时，要加"忽略原图上的文字与装饰，只把商品本身当主体"，否则连原图的横幅一起搬过来。

### 8-C 字要准的图：不走 AI 生图

分享卡、说明图、排版稿这类，做法是：

1. **用 HTML 排版**：字号、行距、颜色、位置全部可控。
2. **无头浏览器渲染截图**：定好画布尺寸（比如 750×600、750×750），截出 640×512（5:4）和 640×640（1:1）。
3. **要真像素就用 2 倍画布**：1440×1080 做 2 倍超采样，再缩到目标尺寸，边缘才不毛。
4. **Pillow 兜底**：简单标题图直接用 Pillow 写字，比 AI 稳。

为什么不用 AI：AI 写中文长句必崩，而且每次崩的地方不一样；排版图要的是"每次都对"。

### 8-D 公众号抬头图 / 分享卡

- **抬头图**：起宣传作用，不放价格卖点。尺寸按文章排版宽度定（如 1440×1080），Pillow 2 倍超采样。
- **分享卡**：产品级通用卡，所有文章共用一张。曾做 1000×800（5:4，小程序分享图比例），左栏品牌条 + 标题 + 能力总括，右栏 2×2 四张示例图，底部搜一搜文案。
- **不要画微信界面的角标**：来源名、小程序角标是微信自己渲染的，画进分享图里是错的。
- **标题描边要看清底色**：米白底上的白字加白描边等于没描边，那次改成实心彩字加硬投影才对。

---

### 8-E 图标与站点图标

图标和别的图不是一回事，它要经得起缩小。

1. **先想 16px**：标签页图标只有 16 像素，剩下的只有轮廓。图形超过三条线就别指望。
2. **能用 SVG 就用 SVG**：位图放大会软。长期用要拿到矢量源（AI / EPS / SVG），或者要求直接出 SVG。
3. **要透明底**：提示词写"透明背景"，不要白底、不要棋盘格——画出来的棋盘格不是透明。
4. **出一张，缩到 16px 看一眼**：糊了就简化线条，再出。
5. **导出四个尺寸**：512、192、180、40。
6. **放对位置**：网页图标 `app/icon.png`（512）、苹果图标 `app/apple-icon.png`（180），官网和控制台各放一份。
7. **深浅底都试**：放在深色和浅色背景上各看一眼，边缘有没有一圈白边。

**一次真实教训**：原来的站点图标是自画的"蓝方块 + Z 折线"，缩到 16px 就糊成一条；后来换成官方图形裁切版才看清轮廓。代价是位图来源只有 195×114，放超大尺寸会偏软——所以第 2 条才说能拿矢量就拿矢量。

## 9. 验收清单

1. 比例和用途对得上，放页面上不拉伸。
2. 图里没有乱码、没有多余文字。
3. 主体完整，没被裁掉一半。
4. 压上字以后字清楚（真压上去看）。
5. 裁切落在有细节的地方。
6. 色调和页面里其他图是一套。
7. 体积合理（单张 700KB 以内，后台上传 ≤1MB）。
8. 文件名带版本，没覆盖旧文件。
9. 引用和图片文件一起提交，页面实测能加载。
10. 手机上再看一眼。
11. 预览版用的是独立文件，正式页没被带着改。
12. 图里没有别人的品牌、水印、二维码。

## 10. 排错表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 图里出现奇怪的中文 | 让模型写了成句文字 | 删掉，改 HTML 排 |
| 白字看不清 | 图太亮 | 亮度乘 0.7 左右 |
| 整块发黑、看不出内容 | 压太狠 | 回退到 0.85 左右 |
| 窄条像一条纯色 | 裁在纯色区 | 下移到云层/纹理段（0.58 附近） |
| 改一处，别处也变 | 没写"保持不变" | 补清单，重来 |
| 改五轮越来越糊 | 结构本来就不对 | 丢掉，重写提示词 |
| 商品被重画成相似品 | 缺保真段 | 逐项点名结构 + 只允许改什么 |
| 商品被换成别的类目 | 提示词写死了具体颜色/配件 | 改成限定"哪类商品" |
| 人物脸变了 | 没列必须保住的部分 | 脸、发型、肤色、姿态逐条写 |
| 标签上的品牌名没了 | 提示词要求"自编小字" | 改成"标签文字原样保留" |
| 图里冒出 UPF50+ 这类参数 | 模型自造 | 显式禁止自造参数 |
| 一套图色调不统一 | 每张单独调 | 固定统一段，统一后处理 |
| 页面图裂了 / 404 | 只提交了引用 | 图片本体一起提交 |
| 对方看到的还是旧图 | 同名覆盖 + 缓存 | 换新文件名 |
| 手机上看糊 | 字号按原图算的 | 按缩后尺寸重定字号 |
| 出图 403 insufficient_user_quota | 通道余额不足 | 查余额，不是提示词问题 |
| 出图 400 content_policy | 内容审核 | 原样再跑一次通常就过 |
| ECONNRESET / SSLEOF | 瞬时网络错误 | 间隔 5 秒重试，最多 4 次 |
| 出图糊、有涂抹感 | AI 生图本身的特征 | 缩略看，或换更大的原图 |
| 小尺寸下糊成一团 | 图形太复杂，或位图被放大 | 简化线条，或换矢量源 |
| 图里出现真实品牌 / 水印 | 模型学到了库里的素材 | 重出并禁止 logo/水印；仍出现就换构图 |
| 改了预览页，正式页也变了 | 两边共用同一张图 | 给预览版建独立文件 |
| 透明底不透明 | 出了白底或棋盘格 | 明确写"透明背景"，并检查 alpha 通道 |

## 12. 节奏与花费

- 一张能用的图：1 张试方向 + 3 到 5 轮微调。
- 单张出图 20 到 40 秒，算上压暗、裁切、检查，半小时内能定。
- 改图也是一次计费，改图前把要求写全，能省一轮就是省一次。
- 同一提示词连出三张同一个毛病，是提示词的问题，别继续抽。
- 方向没定就批量，是最大的浪费。

---

## 13. 归档

- **提示词原文存下来**，和成品放一起，下次改两个字就能复用。
- **成品按语义 + 版本命名**，旧版留一到两版做对比。
- **过程件单独放**（对照图、试验图），发布前清掉。
- 一套图一个文件夹：成品、提示词、出图记录。
