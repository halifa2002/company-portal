# 前端约束清单（依据领导《公司品牌化二次开发技术方案》）

> 来源：`../../new-api/company/writing-block.md`（755 行，十二章 45 小节）
> 适用：本仓库 `apps/website`、`apps/console`、`packages/*`
> 制定：2026-11-13 ｜ 依据行号对应该文件当前版本

这份文件把领导方案里**与前端有关**的要求抽出来，写成可以逐条打勾的约束。方案本身是工程技术规范，不是设计稿——它管的是「不许越界」，不是「好不好看」。所以下面每一条都给了判据和检查方式，能核对的就不靠感觉。

---

## 0. 怎么用

1. **提 PR 前**逐条对照第 1～6 节，全部满足才能提。
2. **写代码时**在注释里标约束编号，例如 `// 守 7.1 C-V-03：只用品牌蓝族`，方便审计时反查。
3. **每周**跑一次附录 A 的自检命令，数字进周报。

分级：

- **MUST**：不满足即不合规，领导验收会直接打回。
- **MUST NOT**：明文禁止，出现就是缺陷。
- **SHOULD**：应当遵守，确有理由时需在 PR 里写明理由。

## 1. 视觉方向（方案 7.1，412–426 行）

| 编号 | 级别 | 约束 | 判据 |
|---|---|---|---|
| C-V-01 | MUST | 浅色主题为默认主题 | 首屏与全站默认底色为浅色，无深色模式兜底伪装成默认 |
| C-V-02 | MUST | 深色文字 + 浅色背景 | 正文对比度 ≥ 4.5:1，正文不用白字压深底（深色块只做区段，不做默认） |
| C-V-03 | MUST | 蓝色或靛蓝色作为品牌强调色 | **全站强调色只有一个色相**；橙、绿、紫不得作为强调色出现 |
| C-V-04 | MUST | 品牌色值由设计阶段确定后**写进 tokens** | 换色只改一处（见 C-S-01） |
| C-V-05 | SHOULD | 留白充足 | 区块间距 ≥ 80px（桌面），不靠堆内容填满 |
| C-V-06 | MUST | 页面信息层级明确 | 每屏一个主标题，字号序列可数（display / heading / title / body / meta） |
| C-V-07 | MUST | 卡片边框轻量化 | 边框 1px 且透明度低；不用重描边+阴影+发光三件套 |
| C-V-08 | MUST | **适度**使用圆角 | 圆角取自 tokens 的 8/12/16/24 四档，不出现 0 或 40px 这类自定值 |
| C-V-09 | MUST | 图表简洁 | 用量/趋势图不上渐变填充+多色系列+网格三叠加 |
| C-V-10 | MUST | 控制台避免过多装饰性元素 | `apps/console` 无跑马灯、无网点/色带背景、无逐字动画 |

> 7.1 九条全是「减法」词，没有一条要求「有设计感 / 有视觉冲击」。**不要用「好不好看」当验收标准**——方案里没有这个维度。

## 2. 设计系统（方案 7.2，428–444 行）

| 编号 | 级别 | 约束 | 判据 |

## 3. 内容真实性（方案 4.1 / 4.2 / 9.1）

这是领导最容易挑出问题的一类，也是最容易自查的一类。

| 编号 | 级别 | 约束 | 原文出处 |
|---|---|---|---|
| C-D-01 | MUST | 价格**必须以后端计费规则为准** | 4.1 定价页，215 行 |
| C-D-02 | MUST NOT | 不能只在前端写死价格 | 同上 |
| C-D-03 | MUST | 只有**实际接入并验证**的能力才能展示为可用 | 4.2 B，272 行 |
| C-D-04 | MUST NOT | 不允许用静态模拟数据冒充正式统计 | 4.2 A，247 行；十一章第 5 条，730 行 |
| C-D-05 | MUST | 厂商 / 模型 / 协议数量的**口径全站唯一** | 9.1 要求「模型价格与实际计费一致」 |
| C-D-06 | MUST NOT | 生产页面不得出现 `example.com`、`待定`、`support@example.com` 这类占位 | 十二章最终交付，741–753 行 |

**C-D-05 的落地要求**：模型清单只有一个真源（`packages/types/src/model-catalog.ts` 与后端 `/api/pricing` 取交集），首页厂牌带、模型区、页脚、文档页四处引用的数字必须由同一份数据推导，不得写死常量。

## 附录 A：自检命令（PowerShell，在仓库根执行）

```powershell
# 1. 业务代码里的裸色值（C-S-02，目标 0）
Get-ChildItem apps -Recurse -File -Include *.tsx,*.ts,*.css |
  Where-Object { $_.FullName -notmatch 'node_modules' } |
  Select-String -Pattern '#[0-9a-fA-F]{3,6}' | Measure-Object | % Count

# 2. tokens 里是否混进非蓝强调色（C-V-03 / C-S-03，目标 0）
Select-String -Path packages\design-tokens\src\theme.css -Pattern 'accent-(warm|lime)'

# 3. 生产代码里的占位符（C-D-06，目标 0）
Get-ChildItem apps -Recurse -File -Include *.tsx,*.ts,*.md |
  Where-Object { $_.FullName -notmatch 'node_modules|preview' } |
  Select-String -Pattern 'example\.com|待定'

# 4. 厂商清单是否还有写死常量（C-D-05，目标 0）
Select-String -Path apps\website\components\*.tsx -Pattern "const VENDORS"

# 5. 类型与构建
bun run typecheck
bun run build
```
