# @portal/ui

品牌官网与用户控制台共用的界面零件。

## 为什么有这一层

领导文档 3.2 要求前端仓库里有统一的 `ui` 组件包。官网和控制台是两个独立的 Next.js 应用，
但「复制按钮」「空状态」「加载骨架」这类零件长得一样，放这里只维护一份。

文档 7.2 还要求「禁止每个页面自行定义一套颜色和间距」。所以从 2026-11-12 起，
控制台的基础部件（按钮、输入、卡片、表格、弹窗、状态标签）也收进这里，
页面只调用部件、不再自己拼样式。

## 现有组件

| 组件 | 用途 |
| --- | --- |
| `Button` / `buttonClass` | 四种语气（primary / secondary / ghost / danger）× 两个尺寸；自带提交中转圈、按下回弹 |
| `Input` / `Select` / `Textarea` | 输入类控件，共用一套边框、焦点环、禁用态 |
| `Field` | 表单一行：标签 + 控件 + 说明 + 错误，间距固定 |
| `Card` / `CardHeader` / `Notice` | 内容分组容器，内边距固定 24，圆角 12 |
| `TableWrap` / `THead` / `Th` / `Tr` / `Td` / `TdSub` | 表格零件，表头浅灰底、行高固定、自带横向滚动 |
| `Modal` / `ConfirmDialog` | 弹窗与二次确认，支持 Esc、焦点归还、背景锁滚动 |
| `Badge` | 状态标签，语义色浅底 + 深字 + 圆点（不靠颜色单独传达状态） |
| `CopyButton` | 复制文本，1.5 秒后提示「已复制」 |

## 约定

- 只放**与业务无关**的零件。带接口调用、带路由跳转的组件放各自 app 里。
- 样式只用设计变量（`text-ink`、`border-line`、`rounded-control`、`p-card` 等），不写死颜色和像素。
- 尺寸类（`w-full` / `w-60`）不要写进组件基础样式里：Tailwind 的类按生成顺序生效、
  不按字符串顺序，基础类里有 `w-full` 再传 `w-60`，谁赢是随机的。宽度一律由调用方给。
- 新增组件时补一行到上表，并在 `src/index.ts` 导出。
